# Bir Stars

Поздравительный сайт для CEO: тизер, второй ролик и звёздное небо, где каждая звезда — поздравление от коллеги.

| Адрес | Что там |
|---|---|
| `/` | Тизер. Ссылка «Смотреть продолжение» появляется, когда её включают в админке |
| `/force` | Второй ролик и кнопка перехода к небу (прыжок в гиперпространство) |
| `/galaxy` | Звёздное небо |
| `/admin` | Админка: звёзды, тексты, ролики, журнал открытий |

Весь сайт закрыт паролем получателя, админка — отдельным паролем редактора. Поисковикам индексация запрещена.

Стек: Cloudflare Worker со статическими файлами (`public/`) и серверной частью (`src/index.js`, `lib/`) + база Cloudflare D1. Настройки — в `wrangler.jsonc`. Ролики — Cloudflare Stream или YouTube. Сборки нет: Cloudflare публикует репозиторий как есть после каждого изменения в `main`.

## Подключение Cloudflare (один раз)

Проект `birstars` уже создан в **Workers & Pages** и подключён к GitHub. Каждое изменение в ветке `main` публикуется автоматически (вкладка **Deployments**).

### 1. Пароли
Проект `birstars` → **Settings** → **Variables and secrets** → **Add**, тип **Secret**:
- `SITE_PASSWORD` — пароль для CEO (его вы отправите в SMS);
- `ADMIN_PASSWORD` — пароль для админки;
- `TEST_PASSWORD` — необязательный тестовый пароль для команды. Его вводят на том же экране, что и пароль CEO.

Нажмите **Deploy** и проверьте во вкладке **Deployments**, что активна самая новая версия. Пароли сохраняются между публикациями. Смена `SITE_PASSWORD` или `ADMIN_PASSWORD` выходит из сайта на всех устройствах, включая устройства CEO. Смена `TEST_PASSWORD` выходит только у тестировщиков.

**Тестовый режим.** По тестовому паролю, а также из админки, сайт выглядит так же, как у CEO при первом заходе: чистое небо, текст под вторым роликом появляется после просмотра. Заходы, «досмотрел» и прочитанные звёзды на сервер не пишутся — прогресс хранится только в браузере тестировщика. В углу видна метка «Тестовый режим · Выйти». «Выйти» выходит из всех входов на этом устройстве, включая админку. У CEO кнопки выхода нет.

### 2. База данных D1
1. **Storage & Databases** → **D1 SQL Database** → **Create database** → имя `birstars`.
2. Скопируйте **Database ID** и впишите его в `wrangler.jsonc` в блок `d1_databases`:
   ```jsonc
   "d1_databases": [{ "binding": "DB", "database_name": "birstars", "database_id": "<ID>" }],
   ```
   Добавлять привязку через дашборд не нужно: при следующей публикации её заменит `wrangler.jsonc`.

Таблицы создаются сами при первом открытии сайта.

Готово: `https://birstars.<ваш-поддомен>.workers.dev/admin` (точный адрес — кнопка **Visit** в проекте).

## Ролики в Cloudflare Stream
1. Cloudflare → **Stream** → подключите тариф (около 5 долларов в месяц).
2. **Upload** → загрузите ролик и дождитесь обработки.
3. Откройте ролик → вкладка **Embed** → скопируйте код встраивания или ссылку.
4. Админка → **Тексты и ролики** → вставьте в поле «Ролик». Под полем появится «Распознано: Cloudflare Stream» — значит, всё верно.

Кадр-обложку можно выбрать в настройках ролика в Stream (Thumbnail). Подойдёт и ссылка на YouTube — поле распознаёт оба варианта.

## Домен birstars.az
1. Cloudflare → **Add a domain** → `birstars.az` → бесплатный тариф.
2. Cloudflare покажет два NS-сервера. У регистратора .az замените NS-серверы домена на них. Активация занимает от нескольких минут до суток.
3. Проект `birstars` → **Settings** → **Domains & Routes** → **Add** → **Custom domain** → `birstars.az`.

Вход запоминается отдельно для каждого домена, поэтому CEO отправляйте только ссылки на `birstars.az`.

## Видео-поздравления и иконки
- **Видео на звезде.** Загрузите вертикальный ролик в Stream, откройте звезду в админке и вставьте ссылку в поле «Видео». При нажатии на звезду откроется ролик, текст поздравления станет подписью под ним (можно оставить пустым).
- **Иконка звезды.** В той же форме выберите «Кружок» (обычная звезда) или «Сердечко».
- **Новая иконка.** Положите белый SVG (квадратный, прозрачный фон) в `public/assets/icons/` и добавьте строку в `public/assets/icons.js`. После публикации иконка появится в админке.

## Уведомления в Telegram
Когда CEO впервые открывает тизер, второй ролик, небо, досматривает второй ролик до конца и прочитывает все звёзды, в Telegram приходит сообщение. Заходы по тестовому паролю и из админки уведомлений не присылают.

1. В Telegram откройте **@BotFather** → `/newbot` → придумайте имя → скопируйте токен вида `123456:ABC…`.
2. Откройте своего нового бота и нажмите **Start** — без этого бот не может вам писать.
3. Узнайте свой ID: напишите **@userinfobot**, он ответит числом (Id). Если уведомления нужны нескольким людям, каждый жмёт Start у бота и узнаёт свой ID; ID перечисляются через запятую.
4. Cloudflare → проект `birstars` → **Settings** → **Variables and secrets** → **Add**, тип **Secret**:
   - `TG_BOT_TOKEN` — токен из шага 1;
   - `TG_CHAT_ID` — ID из шага 3 (например `123456789` или `123456789,987654321`).
5. **Deployments** → убедитесь, что активна самая новая версия.
6. Админка → **Открытия** → «Отправить тестовое уведомление».

Уведомление о первом открытии приходит один раз на каждую строку журнала; если сбросить строку, следующее открытие снова пришлёт уведомление.

## Перед отправкой ссылки
- Удалите тестовые звёзды и загрузите настоящий список (вкладка «Звёзды» → «Импорт из таблицы»).
- Проверьте тексты и ролики.
- Сбросьте прочитанное и очистите журнал открытий от своих проверок.
- Ссылка «Смотреть продолжение» должна быть выключена до отправки второй ссылки.

## Локальный запуск
```
cp .dev.vars.example .dev.vars        # тестовые пароли
npx wrangler dev                      # локальная копия базы, настоящая не затрагивается
```
Сайт откроется на `http://localhost:8788`.

Шрифт Onest (лицензия OFL, `public/assets/fonts/OFL.txt`) подключён локально и урезан до латиницы, азербайджанских букв и кириллицы.
